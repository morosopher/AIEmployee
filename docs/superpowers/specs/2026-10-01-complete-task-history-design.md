## 1. 问题与目标

当前导航存在“任务历史”入口，但 TasksPage 只按 query.task_id 调用 getTask，恢复一个任务快照及其 SSE。前后端均没有任务列表读取端点。M1/M2 的既有验收记录不作为完整历史分页已经实现的证据，本补充不改写历史发布证据。

目标是让用户在刷新、重新登录后仍可查找 PostgreSQL 中当前用户仍然拥有且尚未清理的任务，从列表进入现有详情，继续使用已有取消、失败重试和恢复提案入口。

“完整”指可遍历当前用户保留中的真实 TaskRun 记录，不是浏览器曾访问的任务缓存，不包括没有 TaskRun 的内部队列作业，也不恢复已删除的数据。

## 2. 已确认的产品范围

包含：

- 默认“业务任务”，可切换“全部任务”。
- 按任务类型、任务状态、创建时间范围筛选；默认不限制创建时间。
- 创建时间倒序，每页默认 20 条，上一页／下一页；并列时间使用任务 ID 确定顺序。
- 摘要、选中任务详情、重试来源关联、保留期删除后的恢复提示。
- 新任务提示、显式刷新及后台失败记录提示。
- 受用户隔离的只读列表接口、查询用例、Repository、必要索引和前端列表状态。

不包含：新增任务种类、通用任务提交器、全文搜索、正文索引、导出、批量操作、历史删除入口、永久归档、新的审批／执行／重试／取消规则、每行 SSE、Redis 历史副本、任务触发来源追溯或新供应商能力。

未提交审批的本地邮件草稿和日程提案不是 TaskRun，仍由操作中心呈现，不为列表伪造任务。

## 3. 分类：按用途，不按触发方式

分类由服务端固定映射计算；不改写历史行，不通过输入正文、幂等键或模型猜测来源。

| 分类 | 现有 kind | 说明 |
|---|---|---|
| business | daily_brief | 手动与定时简报均包含 |
| business | conversation.respond | 已持久化的对话回复任务 |
| business | mail_draft.generate | 邮件正文生成，不等于已发送 |
| business | trusted_action | 已有邮件／日程可信操作任务，不解密命令识别列表标题 |
| business | calendar.restore.prepare | 恢复提案准备，不等于日程已恢复 |
| background | sync_mail、sync_gmail、sync_calendar | 含手动同步与周期同步，sync_gmail 保留旧记录兼容 |
| background | brief.overdue_diagnostic | 简报逾期诊断 |
| background | privacy.clear_source_cache、privacy.delete_all_data | 仅在所属用户仍有读取权限且记录尚存时可见 |
| other | 其余 kind | 未识别、维护或历史种类，统一出现在“全部任务” |

固定 business 集合以外的记录均不会消失在“全部任务”中。未知种类以“其他任务”及经过文本插值的 kind 说明，不推断为业务成功或特定供应商操作。可信操作列表标签为“可信操作（邮件／日程）”，具体动作继续由既有详情／操作中心提供，不为易读标题增加敏感载荷读取。

状态沿用 TaskStatus 的十个值：created、queued、running、waiting_approval、retry_scheduled、reconciling、needs_attention、succeeded、failed、cancelled。不得把断线转成 failed，或把 reconciling／needs_attention 合并为普通失败。

## 4. 列表与详情交互

### 4.1 列表

- 保留导航名称与 `/tasks` 路径。默认业务任务、全部类型、全部状态、全部保留时间，每页 20 条。
- 类型筛选提供上表已知类型及“其他任务”，不新增动态种类目录接口；选择“其他任务”同时切到全部任务。业务视图类型选项限 business 种类。
- 每行显示类型、状态、创建时间、耗时、简短 ID；链接与内部请求使用完整 UUID，短 ID 不能充当资源身份。
- 不显示邮件主题、收件人、正文、输入／结果载荷或由其生成的标题。
- 耗时从 started_at 计算：未开始显示“尚未开始”；有 finished_at 时显示已知执行时长；运行中按响应 server_time 显示“已运行…”，注明列表读取时间，不将排队时间算成执行时间。缺失或无效时间显示未知，不补零或依赖宿主时区。
- 加载、首次空数据、无筛选匹配、加载失败分别呈现；失败保留已有数据并标为刷新失败，不能伪装成空历史。
- 没有任务时保留用户可理解的任务选择／查看提示，不显示未实现的任务创建入口。

### 4.2 详情与原动作

点击行设置既有 `task_id`，保留当前筛选和游标。浏览器刷新、前进／后退及站内任务链接仍能打开该任务；即使任务不在当前筛选结果内，也正常读取其详情，不强行清空筛选。

取消、重试仅在详情执行，继续走原 API、CSRF、幂等键、服务端状态校验及 replacement 跟随。列表不凭摘要推导操作授权；trusted_action 的审批／结果确认仍留在原可信操作界面。

重试产生的 TaskRun 独立成行，展示 retry_of_task_id 的关联；原任务及新任务都保留原状态。关联目标已清理时显示来源记录不可用，不串联到其他任务。已有外键置空后不声称可恢复丢失的来源 ID。

列表不会覆盖 TaskSnapshot、steps、event_cursor 或 SSE 游标。详情只使用现有 getTask/useTaskEvents；同一任务不因列表新增第二条订阅。详情中的动作完成后刷新列表；失败／未知结果按原详情逻辑处理，不自动重新执行。

### 4.3 后台失败提示

业务视图显示“当前时间范围内有 N 条后台失败记录”，N 为当前用户、当前创建时间范围内、非 business 且 status=failed 的记录数，包括 other 分类。N 不受业务类型／状态筛选限制，提示明确说明这一口径；N=0 不显示。

点击提示切到全部任务，选择后台范围和 failed，保留时间范围并重置游标。API 的 background 范围覆盖 background 与 other。界面可用筛选摘要显示“后台任务”，不增加第三个主导航入口。

该计数不是未处理故障数、重试建议或人工确认状态，不因记录很旧或后续另有成功任务而自行核销；不对失败任务自动执行任何动作。

## 5. 只读 API 契约

新增 `GET /api/v1/tasks`；既有 POST 同路径及 `/{task_id}`、`/{task_id}/events`、取消／重试响应不变。

### 5.1 查询参数

| 参数 | 规则 |
|---|---|
| scope | business（默认）、all、background；background 包含 background/other |
| kind | 可选，上表的精确已知 kind 或 other；互斥范围组合返回 422，不静默改义 |
| status | 可选，TaskStatus 的精确值 |
| created_from_date | 可选，YYYY-MM-DD，用户 IANA 时区中的包含起始日 |
| created_to_date | 可选，YYYY-MM-DD，用户 IANA 时区中的包含结束日 |
| limit | 默认 20，1～100；首版界面固定 20 |
| cursor | 可选、有版本、最长 2048 字符的 opaque 游标；客户端不解释内容 |

服务端使用当前用户配置的 IANA 时区，把日期范围规范化为 UTC 半开区间；结束边界为结束日期的下一本地日边界，不加固定 24 小时。覆盖 DST 的 23/25 小时日期：重叠的午夜采用该本地日最早有效瞬间，午夜跳跃采用当天首个有效瞬间；整日本地日期被跳过时，该日期对应空区间，不借用另一日期的记录。拒绝倒置区间和非法日期。无时区猜测，不使用主机本地时区。

### 5.2 响应

`items` 中每个 TaskHistoryItem 仅包含：id、kind、category、status、created_at、started_at、finished_at、error_code、retry_of_task_id。可空字段保持 null；不带 steps、event_cursor、input_payload、result_payload、租约、幂等键、Checkpoint 或供应商身份信息。

分页响应包含：items、next_cursor、previous_cursor、server_time、filter_timezone、background_failed_count。两个游标无对应方向时为 null；server_time 为带时区 UTC。filter_timezone 明示日期筛选实际采用的 IANA 时区。没有总页数或任意跳页承诺。

所有成功与失败响应遵守既有 Problem Details 边界，列表响应 `Cache-Control: no-store`。认证失败沿用现有 401；非法过滤／日期为 422 `task_history_filter_invalid`；无效、篡改、过期、版本不支持或用户／筛选不匹配游标均为 422 `task_history_cursor_invalid`，不回显游标或认证信息。

正常清理造成列表为空返回 200 空数组。详情 404 仍统一隐藏不存在和跨用户记录；界面显示“任务记录已不可用”，不声称一定因保留期删除，也不尝试从浏览器缓存恢复事实。

## 6. 稳定分页与并发语义

排序固定 `(created_at DESC, id DESC)`，seek 比较使用完整精度时间和 UUID。第一页建立创建顺序上界，后续游标带相同上界及当前方向的边界键；下一页查询更旧记录，上一页反向查询相邻记录后恢复倒序。

游标绑定版本、当前用户、规范化筛选（含时区及 limit）、方向、上界、边界和签发时间，有效期 24 小时。游标载荷只允许固定版本的分页元数据，签名采用 HMAC-SHA256；从现有应用主密钥通过 HKDF-SHA256 派生专用材料，用途标识固定为 `ai-employee/task-history-cursor/v1`，不复用命令哈希或 Cookie 密钥。先限制长度再解码，严格校验载荷类型、精度、枚举和边界，签名使用常量时间比较；签发时间超过当前服务端时间 60 秒或年龄达到 24 小时即拒绝。时钟通过既有 Clock 端口注入，不在测试依赖真实等待。不新增凭据配置，不将游标当作认证凭据。密钥轮换后不再可验证的旧游标返回统一无效错误，界面提供“重新加载列表”，不静默忽略或放宽筛选。

每个请求是一次短期只读数据库读取，不持有跨页面事务。items、分页方向判断与失败计数在同一短只读一致性快照中产生；不得为浏览器翻页保留数据库连接或事务。`limit + 1` 检查分页边界，不把完整任务集合加载到应用内存，也不逐行读取详情或关联载荷；失败计数使用数据库聚合，按实际数据分布验证查询计划。

上界阻止创建顺序更新的任务挤入正在浏览的页，不是冻结全部记录状态的历史快照：状态改变、保留清理以及先创建后提交的事务仍可能改变分页成员。接口不得承诺翻页期间全局无遗漏或冻结总数；刷新从最新第一页重新读取。

游标不依赖边界行继续存在，删除边界行不能导致 500。若清理或状态筛选改变导致当前页为空，保留返回上一页／重新加载入口；不可无限往返同一个游标。过滤条件变化或用户时区变更必须重置分页，跨条件复用游标由服务端拒绝。

## 7. 新任务提示与前端状态

列表仅在任务历史页挂载且文档可见时每 30 秒检查同一筛选的最新一页，复用列表 GET，无新增 SSE 或专用后台作业。同一时间最多一次探测；隐藏、卸载时停止，失败不快速重试。

初次完整读取记录创建顺序头部；探测发现更新的匹配记录时仅提示“有新任务，点击刷新”，不替换正在浏览的内容、不自动跳页或抢焦点。对排序落后于头部的迟提交记录不承诺即时新增提示；手动刷新和再次遍历仍从数据库读取真实记录。

用户手动刷新、切换筛选、页面恢复可见／重新进入、详情取消或重试完成后重新读取。切回页面优先重新读取当前页；主动刷新／新任务提示从第一页开始。请求使用世代标识或取消机制，旧筛选、旧页或卸载后的响应不得覆盖当前视图。

列表状态放在独立 `features/tasks/useTaskHistory.ts`，只维护摘要和分页，不复用 `stores/tasks.ts` 的完整快照写入入口。详情仍由既有 Task Store 和 useTaskEvents 管理。列表查询失败不改变详情状态，SSE 断线不使历史记录失败。

URL 只保存公开的过滤参数、opaque 游标和 task_id，不保存正文、账户地址或错误载荷；不写 localStorage/sessionStorage。不修改认证路由守卫。原 `/tasks?task_id=...` 链接保持兼容。

## 8. 分层、索引与限定修改范围

调用方向：现有 tasks router → 独立 ListTaskHistoryUseCase → 只读查询 Repository → task_runs。分类和过滤规范化为可独立测试的应用规则；ORM 类型不进入 API 或前端。

预计新增或扩展的必要路径：

- `backend/src/ai_employee/api/routers/tasks.py`：新增列表响应与 GET；原端点契约不改。
- `backend/src/ai_employee/api/deps.py` 及既有组合根：仅注入新查询用例。
- `backend/src/ai_employee/application/use_cases/task_history.py`：摘要、筛选、分页用例与查询端口。
- `backend/src/ai_employee/infrastructure/db/repositories/task_history_views.py`：新只读查询；不得与现有 `task_history.py` 保留清理器混用。
- 现有安全基础设施内新增专用 cursor codec：复用主密钥体系，完成有界解码、用途隔离签名和统一错误映射；不改变 OAuth／命令加密协议。
- `backend/src/ai_employee/infrastructure/db/models/tasks.py` 及一条 Alembic 迁移：仅增加查询索引，优先 `(user_id, created_at, id)`；通过合成数据查询计划确认状态筛选索引的必要性后才增加额外索引。
- `frontend/src/api/taskHistory.ts` 及其契约测试：独立严格摘要解析，不降低现有 API 校验。
- `frontend/src/features/tasks/useTaskHistory.ts` 及测试：独立列表状态与可见性探测。
- `frontend/src/pages/TasksPage.vue`、对应测试及必要列表展示组件：组合真实列表和现有详情。
- 后端单元／集成／API 契约测试、前端单测／E2E、相关规则和验收文档。

索引迁移必须通过既有 Alembic、schema lifecycle 和 schema/ACL 审计流程，不添加角色或权限，不绕过迁移守卫。不得未经证据就声称 `CREATE INDEX CONCURRENTLY` 原子回滚；具体索引部署步骤在实施计划中按现有迁移框架落实并测试。

禁止修改任务创建事务、TaskRun 状态机、Worker、Scheduler、Taskiq 投递、Outbox、Checkpoint、清理器、真实供应商调用、审批／幂等规则及现有 SSE 协议。本规格的后台分类不要求修改每个任务创建点或添加 origin 字段。

## 10. 验收清单

以下均为实施后的验收要求，本设计提交不勾选：

- [ ] PostgreSQL 保留任务可分页找回，刷新后不依赖浏览器曾访问记录；默认业务分类与完整种类表一致。
- [ ] 手动／定时简报同属业务；手动同步、诊断、隐私清理和未知类型可从全部任务找到；无 TaskRun 的作业不伪造条目。
- [ ] 类型／状态／创建日期组合、空范围、无匹配、DST 23/25 小时、午夜重叠／跳跃、整日跳过与宿主时区不同的场景正确；默认无日期限制。
- [ ] 默认20、上下限、同时间多UUID、双向翻页、插入新任务、状态变化、边界删除、清理后空页与重新开始均有真实PostgreSQL回归。
- [ ] 游标错误版本、过长／畸形、篡改、过期、跨用户、跨筛选／时区／limit、签名密钥变化均安全拒绝；日志不回显游标载荷或秘密。
- [ ] items、后台失败计数和查询均强制注入 user_id；跨用户身份、计数、任务链接均不可泄露。
- [ ] 摘要精确字段白名单及 no-store 通过；不读取／解密／返回输入正文、结果载荷、步骤、租约、供应商身份或凭据。
- [ ] 后台失败提示只计当前时间范围非业务failed，跳转条件精确；不暗示尚未处理或自动重试。
- [ ] 重试独立成行及来源关联正确；详情取消／重试／恢复入口、幂等与唯一外部执行回归保持。
- [ ] 列表响应不覆盖完整TaskSnapshot或SSE游标；详情仍只订阅一条既有事件流，列表无每行SSE。
- [ ] 可见性探测30秒、无并发探测、后台停止、卸载清理、迟到响应隔离、新任务提示不跳页及刷新恢复通过可控时间／网络测试。
- [ ] 键盘筛选、翻页、打开详情、返回列表、焦点保留、错误恢复、窄屏和桌面布局有浏览器测试；live region按M2.1规则登记。
- [ ] 新索引在合成数据上有EXPLAIN证据，无N+1或全量读取；迁移及schema/ACL门禁通过，无共享数据库手工修补。
